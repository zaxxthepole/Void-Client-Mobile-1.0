# Add Minecraft Bedrock 1.26.10 (Protocol 944) Support

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Add support for Minecraft Bedrock Edition 1.26.10-1.26.13 (protocol version 944) to the Voidclient relay proxy.

**Architecture:** The relay protocol library is vendored (copied) from CloudburstMC/Protocol into elay/Protocol/bedrock-codec/. Each MC version has a corresponding Bedrock_vXXX.java class that extends the previous version's codec. The v924 codec extends our existing v898, so no intermediate versions are needed. However, v924 and v944 introduce 13 new packet types that require new Java class files, updates to BedrockPacketType, and updates to BedrockPacketHandler.

**Tech Stack:** Java (codec classes), Kotlin (CodecRegistry, VersionDetector), Gradle build system, CloudburstMC Protocol library (upstream source).

## Global Constraints

- All code must compile with Java 17 / Kotlin 2.2.20
- Protocol library is vendored in elay/Protocol/ — NOT a git submodule
- The v729 inventory serializer override must be checked for compatibility with new versions
- Existing codec versions (291-898) must not be broken
- The getClosestCodec() fallback mechanism means unknown versions will fall back to v898 if v944 isn't registered
- Build runs on GitHub Actions CI (no local Android SDK)
- Signing config uses uildKey.jks with alias VoidclientKey
- Package: com.voidclient.client
